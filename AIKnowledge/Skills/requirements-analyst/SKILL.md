# 需求分析专家 (Requirements Analyst)

## 📋 技能概述

专业需求分析技能，基于 IEEE 830 标准和最佳实践，帮助收集、分析、优先级排序用户需求，并生成标准化的需求规格文档。

## 🎯 适用场景

- ✅ 新项目启动阶段
- ✅ 功能迭代需求分析
- ✅ 用户需求不明确时
- ✅ 需要绘制用例图
- ✅ 需求优先级排序
- ✅ 编写需求规格说明书

## 🔄 工作流程

### 步骤 1：利益相关者识别

识别所有 stakeholders：
- 客户/甲方
- 最终用户（不同角色）
- 产品经理
- 运维团队
- 业务专家
- 技术团队

### 步骤 2：需求收集

使用适当方法收集需求：
- **访谈** - 深入了解特定用户需求
- **问卷调查** - 大范围收集用户意见
- **观察法** - 理解现有业务流程
- **竞品分析** - 了解行业标准
- **头脑风暴** - 创新功能挖掘

### 步骤 3：需求分析

#### 功能需求（使用用户故事格式）
```
作为 [角色]，我希望 [功能]，以便 [价值]
```

#### 非功能需求分类
| 类别 | 说明 | 示例 |
|------|------|------|
| 性能 | 响应时间、吞吐量 | API 响应 < 200ms |
| 安全 | 认证、授权、加密 | 使用 JWT 认证 |
| 可用性 | SLA、容错 | 99.9% 可用性 |
| 兼容性 | 浏览器、设备、系统 | 支持 Chrome、Firefox |
| 可维护性 | 代码规范、文档 | 代码覆盖率≥80% |

### 步骤 4：需求优先级排序（MoSCoW 方法）

```
M - Must have（必须有）
    核心功能，缺少则系统无法运行
    
S - Should have（应该有）
    重要功能，但可短期妥协
    
C - Could have（可以有）
    期望功能，资源允许时实现
    
W - Won't have（暂不需要）
    未来版本考虑
```

### 步骤 5：用例图绘制

#### 参与者识别
- **主要参与者**：发起交互的角色
- **次要参与者**：被动响应的角色

#### 用例识别
- 核心业务用例
- 辅助功能用例
- 管理维护用例

#### 关系定义
- **关联（Association）**：参与者与用例的连接
- **包含（Include）**：用例之间的必要包含
- **扩展（Extend）**：用例的条件扩展
- **泛化（Generalization）**：参与者的继承关系

### 步骤 6：需求文档编写

生成《需求规格说明书》，包含：
1. 项目背景和目标
2. 用户类别和特征
3. 功能需求列表
4. 非功能需求列表
5. 用例图和规约
6. 验收标准

## 📝 示例交互

### 示例 1：电商系统需求分析

**用户**：
```
请分析一个电商系统的需求，主要功能包括：
- 用户注册登录
- 商品浏览搜索
- 购物车管理
- 订单下单支付
- 物流跟踪
```

**Requirements Analyst**：
```
## 需求分析报告 - 电商系统

### 1. 利益相关者识别
- **顾客**：浏览商品、下单购买
- **商家**：管理商品、处理订单
- **管理员**：用户管理、系统配置
- **支付系统**：处理支付（次要参与者）
- **物流系统**：提供物流信息（次要参与者）

### 2. 功能需求（用户故事）

#### 用户管理模块
- 作为顾客，我希望注册账号，以便购物
- 作为顾客，我希望登录系统，以便访问个人信息
- 作为管理员，我希望管理用户，以便维护系统安全

#### 商品管理模块
- 作为顾客，我希望浏览商品，以便了解商品信息
- 作为顾客，我希望搜索商品，以便快速找到目标商品
- 作为商家，我希望上架商品，以便销售

#### 购物车模块
- 作为顾客，我希望添加商品到购物车，以便批量购买
- 作为顾客，我希望修改购物车数量，以便调整购买计划

#### 订单模块
- 作为顾客，我希望下单支付，以便购买商品
- 作为顾客，我希望跟踪物流，以便了解配送进度
- 作为商家，我希望处理订单，以便发货

### 3. 非功能需求

#### 性能需求
- 商品搜索响应时间 < 500ms
- 订单提交响应时间 < 1s
- 支持 1000 并发用户

#### 安全需求
- 使用 HTTPS 加密传输
- 密码使用 bcrypt 加密存储
- 支付使用 Token 验证

#### 可用性需求
- 系统可用性 99.9%
- 支持 7×24 小时运行

#### 兼容性需求
- 浏览器：Chrome、Firefox、Safari、Edge
- 设备：PC、Mobile、Tablet

### 4. 需求优先级（MoSCoW）

**Must have**：
- 用户注册登录
- 商品浏览
- 购物车管理
- 订单下单

**Should have**：
- 商品搜索
- 物流跟踪
- 订单管理（商家）

**Could have**：
- 商品推荐
- 优惠券系统
- 评价系统

**Won't have**：
- 直播带货
- AR 试穿

### 5. 用例图

```

- 顾客（主要）
- 商家（主要）
- 管理员（主要）
- 支付系统（次要）
- 物流系统（次要）

核心用例：
- 注册/登录
- 浏览商品
- 搜索商品
- 管理购物车
- 下单支付
- 管理订单
- 管理商品
