# 技能管理专家 (Skill Keeper)

## 📋 技能概述

专业技能管理技能，负责技能全生命周期管理，包括技能更新、版本控制、质量检查、重构优化和文档维护，确保技能系统持续改进和保持高质量。

## 🎯 适用场景

- ✅ 需要更新现有技能
- ✅ 需要重构技能内容
- ✅ 需要版本管理
- ✅ 需要质量检查
- ✅ 需要合并多个技能
- ✅ 需要创建技能更新日志

## 🔄 工作流程

### 步骤 1：技能分析

#### 分析内容
- [ ] 技能当前版本

- [ ] 技能质量问题
- [ ] 需要改进的方面

### 步骤 2：版本管理

#### 版本号规范（Semantic Versioning）
```
格式：MAJOR.MINOR.PATCH

- MAJOR (主版本号): 不兼容的变更
- MINOR (次版本号): 向后兼容的功能新增
- PATCH (修订号): 向后兼容的问题修复
```

#### 版本变更类型
| 变更类型 | 说明 | 版本号变更 |
|---------|------|-----------|
| 重大重构 | 技能结构或核心理念变更 | 1.0.0 → 2.0.0 |
| 功能新增 | 添加新工作流程或能力 | 1.0.0 → 1.1.0 |
| 内容优化 | 改进示例、说明 | 1.0.0 → 1.0.1 |
| 错误修复 | 修复错误内容 | 1.0.0 → 1.0.1 |

#### 更新日志格式
```markdown
## [版本号] - YYYY-MM-DD

### 新增
- [新增内容 1]
- [新增内容 2]

### 改进
- [改进内容 1]
- [改进内容 2]

### 修复
- [修复内容 1]
- [修复内容 2]

### 移除
- [移除内容 1]

### 变更说明
[详细说明变更原因和影响]
```

### 步骤 3：技能更新

#### 更新原则
- **保持格式一致**：遵循技能模板格式
- **向后兼容**：尽量不影响现有使用
- **持续改进**：基于反馈持续优化
- **文档完整**：更新内容及时记录

### 步骤 5：技能重构

#### 重构场景
- 技能内容过多，需要拆分
- 多个技能职责重叠，需要合并
- 技能结构不合理，需要调整
- 技能内容过时，需要更新

#### 重构流程
```
1. 分析现状
   ↓
2. 制定方案
   ↓
3. 备份原文件
   ↓
4. 执行重构
   ↓
5. 质量检查
   ↓
6. 更新文档
   ↓
7. 通知用户
```

#### 重构示例
```markdown
## 技能重构报告

### 重构原因
- 原技能内容过多（超过 1000 行）
- 职责不够聚焦
- 使用场景不够清晰

### 重构方案
**原技能**: skill-name
**拆分为**:
- skill-name-core (核心功能)
- skill-name-advanced (高级功能)
- skill-name-utils (工具功能)

### 变更影响
- **影响范围**: [描述]
- **迁移方案**: [说明]
- **兼容性**: [是否向后兼容]

### 执行结果
- [x] 原技能已备份
- [x] 新技能已创建
- [x] 文档已更新
- [x] 用户已通知
```

#### 详细步骤

**步骤 5.1：识别参与者**

2. 区分主要参与者（发起交互）和次要参与者（被动响应）

**步骤 5.3：定义关系**

2. 用例之间的包含关系（include）
3. 用例之间的扩展关系（extend）
4. 用例之间的泛化关系（generalization）

**步骤 5.4：绘制用例图**
