# 部署运维专家 (DevOps Engineer)

## 📋 技能概述

专业部署运维技能，基于 DevOps 最佳实践，负责部署方案设计、上线检查、监控配置、运维手册编写和应急预案制定，确保系统稳定运行。

## 🎯 适用场景

- ✅ 项目准备部署
- ✅ 需要上线方案
- ✅ 需要配置监控告警
- ✅ 需要编写运维手册
- ✅ 需要制定应急预案
- ✅ 系统上线后运维

#### 告警规则示例
```yaml
# alerts.yml
groups:
  - name: system_alerts
    rules:
      - alert: HighCPUUsage
        expr: 100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "CPU 使用率过高"
          description: "{{ $labels.instance }} CPU 使用率 {{ $value }}%"
      
      - alert: HighMemoryUsage
        expr: (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100 > 85
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "内存使用率过高"
          description: "{{ $labels.instance }} 内存使用率 {{ $value }}%"
```

- 核心功能不可用
- 数据丢失或泄露

**响应时间**: 5 分钟内

- 部分功能不可用
- 性能严重下降
- 影响大量用户

**处理时间**: 4 小时内

- 非核心功能异常
- 性能轻微下降
- 影响少量用户

**响应时间**: 1 小时内  
**处理时间**: 24 小时内

    ↓

## 4. 常见故障处理

### 故障 1：服务器宕机
**现象**: 服务器无法访问  
**处理**:
1. 确认故障范围
2. 切换到备用服务器
3. 重启故障服务器
4. 检查故障原因

### 故障 2：数据库连接失败
**现象**: 应用无法连接数据库  
**处理**:
1. 检查数据库状态
2. 检查网络连接
3. 检查连接池配置
4. 重启数据库服务

### 故障 3：API 响应缓慢
**现象**: API 响应时间超过阈值  
**处理**:
1. 检查系统资源
2. 检查慢查询
3. 检查依赖服务
4. 限流降级

### 5. 回滚方案

#### 回滚条件
- 核心功能不可用
- 错误率 > 5%
- 响应时间 > 2s
- 数据异常

#### 回滚步骤
```bash
# 1. 停止新版本服务
kubectl rollout undo deployment/app-service

# 2. 恢复数据库（如需要）
mysql -u root -p < backup_rollback.sql

# 3. 验证回滚
curl http://localhost:8080/health

# 4. 通知相关人员
```

#### 回滚时间
- 应用回滚：5 分钟
- 数据库回滚：15 分钟
- 总回滚时间：< 30 分钟
