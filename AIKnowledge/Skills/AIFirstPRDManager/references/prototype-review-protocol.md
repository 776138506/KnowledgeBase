## 第 11 章：原型设计审核（Phase 1.3 专用）

### 11.1 审核维度总览

原型设计审核包含 **8 个核心维度**，每个维度都有明确的检查点和极端情况压力测试。

### 11.2 场景覆盖率审核

**目标**：确保 100% Phase 1 用例都有对应原型页面

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
|-------|---------|---------|
| 用例映射完整性 | 对照 Phase 1 用例图 | 每个用例 ID 都有对应页面 ID |
| 主流程覆盖 | 端到端走查主流程 | 无断点，流程连贯 |
| 异常流程覆盖 | 检查错误场景 | 所有异常都有对应页面/提示 |
| 边界场景覆盖 | 检查极端值场景 | 最大/最小值场景已考虑 |

**极端情况压力测试**：

```
测试场景：用户完成整个流程的所有可能路径
测试方法：遍历所有分支组合
通过标准：每条路径都有对应的页面和交互

示例（用户注册）:
- 主流程：首页 → 注册 → 验证 → 完成 ✅
- 异常流程 1: 邮箱格式错误 → 显示错误提示 ✅
- 异常流程 2: 邮箱已存在 → 显示"该邮箱已被注册" ✅
- 异常流程 3: 密码强度不足 → 实时显示强度提示 ✅
- 边界场景：网络超时 → 显示重试按钮 ✅
```

### 11.3 流程完整性审核

**目标**：主流程和异常流程都完整无断点

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
|-------|---------|---------|
| 主流程连贯性 | 端到端点击测试 | 无 404/断链 |
| 异常流程分支 | 触发所有异常 | 每条异常都有处理路径 |
| 返回/取消逻辑 | 测试返回/取消按钮 | 都能回到合理状态 |
| 成功/失败反馈 | 触发成功/失败场景 | 都有明确提示 |

**极端情况压力测试**：

```
测试场景：所有可能的用户操作组合
测试方法：深度优先遍历所有交互路径
通过标准：每条路径都有明确的下一状态

异常流程示例:
1. 表单验证失败 → 显示错误 → 用户修正 → 重新提交 ✅
2. 网络请求失败 → 显示重试 → 用户点击重试 → 重新请求 ✅
3. 会话过期 → 跳转登录 → 登录成功 → 返回原流程 ✅
4. 并发冲突 → 显示冲突提示 → 提供解决方案 ✅
```

### 11.4 交互一致性审核

**目标**：相同元素在不同页面行为一致

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
|-------|---------|---------|
| 按钮风格 | 对比所有按钮 | 颜色/圆角/阴影一致 |
| 表单验证 | 测试所有输入框 | 验证逻辑/提示样式一致 |
| 导航栏 | 对比所有页面导航 | 位置/样式/链接一致 |
| 加载状态 | 触发所有异步操作 | 加载动画/文案一致 |
| 错误提示 | 触发所有错误 | 提示样式/位置一致 |

**常见不一致问题**：

```
❌ 按钮不一致:
   - 注册页：蓝色圆角按钮
   - 登录页：绿色方角按钮
   → 应统一为蓝色圆角

❌ 表单验证不一致:
   - 邮箱框：实时验证
   - 密码框：提交时验证
   → 应统一为实时验证

❌ 错误提示不一致:
   - 注册页：红色文字在输入框下方
   - 登录页：弹窗提示
   → 应统一为输入框下方红字
```

### 11.5 可访问性审核

**目标**：确保残障用户也能使用产品

**检查清单**：

| 检查项 | 检查方法 | WCAG 2.1 标准 |
|-------|---------|-------------|
| 键盘导航 | 仅用键盘完成所有操作 | Level AA - 2.1.1 |
| 屏幕阅读器 | 使用 NVDA/JAWS 测试 | Level AA - 4.1.2 |
| 颜色对比度 | 使用 Contrast Checker | Level AA - 1.4.3 (≥4.5:1) |
| 焦点可见性 | Tab 键切换焦点 | Level AA - 2.4.7 |
| 表单标签 | 检查所有 input 的 label | Level A - 1.3.1 |
| 图片 Alt 文本 | 检查所有 img 的 alt | Level A - 1.1.1 |

**极端情况压力测试**：

```
测试场景：视障用户使用屏幕阅读器完成注册
测试工具：NVDA + Firefox
测试路径：
1. 打开首页 → 听到页面标题和导航 ✅
2. Tab 键切换到"注册"链接 → 焦点可见 ✅
3. 进入注册页 → 表单字段有 label ✅
4. 输入错误 → 听到错误提示 ✅
5. 提交成功 → 听到成功提示 ✅

通过标准：视障用户无需视力即可完成全流程
```

**工具推荐**：

- **WAVE**: https://wave.webaim.org — 可访问性自动检测
- **axe DevTools**: Chrome 扩展 — 自动化测试
- **Lighthouse**: Chrome 内置 — 可访问性评分
- **Contrast Checker**: https://webaim.org/resources/contrastchecker/

### 11.6 响应式布局审核

**目标**：在所有设备尺寸下都能正常使用

**检查清单**：

| 检查项 | 测试尺寸 | 通过标准 |
|-------|---------|---------|
| 移动端（小屏） | 320px, 375px | 无横向滚动，内容可读 |
| 移动端（大屏） | 414px, 428px | 布局合理，触控友好 |
| 平板端 | 768px, 834px | 充分利用空间 |
| 桌面端（小） | 1024px, 1280px | 居中布局，两侧留白 |
| 桌面端（大） | 1440px, 1920px, 2560px | 不拉伸变形 |

**极端情况压力测试**：

```
测试场景：极端屏幕尺寸下的布局表现
测试方法：Chrome DevTools 响应式模式

极端尺寸测试:
1. 超小屏（320px）: 
   - 单栏布局 ✅
   - 字体不小于 14px ✅
   - 按钮高度≥44px（触控友好）✅

2. 超大屏（2560px）:
   - 内容居中，最大宽度 1200px ✅
   - 图片不模糊 ✅
   - 留白合理，不空旷 ✅

3. 横屏模式:
   - 平板横屏（1024x768）✅
   - 手机横屏（667x375）✅
   - 布局自动调整 ✅
```

### 11.7 加载状态审核

**目标**：所有异步操作都有明确的加载反馈

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
|-------|---------|---------|
| 表单提交 | 点击提交按钮 | 按钮禁用 + 加载动画 |
| 图片加载 | 慢速网络测试 | 占位符/骨架屏 |
| 页面跳转 | 点击导航链接 | 进度条/加载动画 |
| 数据刷新 | 下拉刷新操作 | 刷新动画 |
| 文件上传 | 上传大文件 | 进度条显示 |

**极端情况压力测试**：

```
测试场景：网络极慢（Fast 3G）下的用户体验
测试方法：Chrome DevTools Network Throttling

测试路径:
1. 提交表单 → 按钮立即禁用 + 显示"注册中..." ✅
2. 等待 3 秒 → 用户知道正在处理 ✅
3. 网络超时（10 秒） → 显示"网络超时，点击重试" ✅
4. 用户点击重试 → 重新提交请求 ✅

反面教材:
❌ 点击后无反馈，用户以为没点到，重复点击
❌ 加载 10 秒无提示，用户不知道发生了什么
❌ 超时后页面无反应，用户只能刷新
```

### 11.8 错误处理审核

**目标**：所有错误都有清晰、友好的提示

**检查清单**：

| 检查项 | 检查方法 | 通过标准 |
|-------|---------|---------|
| 表单验证错误 | 输入非法值 | 提示明确，告知如何修复 |
| 网络错误 | 断网/超时测试 | 提示友好，提供重试 |
| 服务器错误 | 模拟 500 错误 | 不暴露技术细节 |
| 权限错误 | 未授权访问 | 引导登录/申请权限 |
| 资源不存在 | 访问 404 页面 | 提供返回首页链接 |

**错误提示质量检查**：

```
✅ 好的错误提示:
- "邮箱格式不正确，请输入类似 name@example.com 的格式"
- "密码长度至少 8 位，当前 5 位"
- "网络连接失败，请检查网络后点击重试"
- "该邮箱已被注册，您可以直接登录或更换邮箱"

❌ 坏的错误提示:
- "输入错误"（太模糊）
- "Invalid input"（英文，部分用户看不懂）
- "Error 500"（暴露技术细节）
- "操作失败"（没告知原因和解决方法）
```

**极端情况压力测试**：

```
测试场景：所有可能的错误都触发一遍
测试方法：故障注入（Chaos Engineering）

错误注入测试:
1. 输入框：空值/超长文本/特殊字符/emoji/SQL 注入 ✅
2. 网络：断网/超时/慢速/不稳定 ✅
3. 服务器：500/502/503/504 ✅
4. 并发：重复提交/多端同时操作 ✅
5. 权限：未登录访问/越权访问 ✅

通过标准：每个错误都有合适的提示和处理路径
```

### 11.9 边界值审核

**目标**：输入框/文件上传等都有合理的边界限制

**检查清单**：

| 检查项 | 测试方法 | 通过标准 |
|-------|---------|---------|
| 文本长度 | 输入最小/最大/超长文本 | 正确截断/提示 |
| 数字范围 | 输入最小值/最大值/溢出值 | 正确校验 |
| 文件大小 | 上传 0KB/刚好/超大文件 | 正确拒绝并提示 |
| 文件类型 | 上传允许/禁止的格式 | 正确识别 |
| 特殊字符 | 输入 emoji/HTML/SQL | 正确转义/过滤 |

**极端情况压力测试**：

```
测试场景：输入框的边界值
测试方法：手动输入 + 自动化测试

邮箱输入框测试:
- 空值 → "邮箱不能为空" ✅
- 正常邮箱（15 字符） → 通过 ✅
- 超长邮箱（254 字符） → 截断或提示"邮箱过长" ✅
- 不含@ → "邮箱格式不正确" ✅
- 含空格 → 自动去除或提示"邮箱不能含空格" ✅
- emoji → 提示"邮箱格式不正确" ✅
- SQL 注入（' OR '1'='1） → 转义处理 ✅

密码输入框测试:
- 空值 → "密码不能为空" ✅
- 7 位 → "密码至少 8 位" ✅
- 8 位 → 通过 ✅
- 128 位 → 提示"密码过长"或接受 ✅
- 纯数字 → 提示"需包含字母和数字" ✅
```
