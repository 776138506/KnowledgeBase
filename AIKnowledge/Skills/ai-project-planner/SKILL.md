# AI 开发项目规划（并行/串行策略）

## 📋 技能目标

在 AI 项目（如机器学习模型训练、智能应用开发、AI 系统集成等）的规划阶段，依据模块间的依赖关系，精准识别可并行开发的模块与必须串行开发的模块，制定出高效、灵活的开发计划，避免传统线性开发造成的资源闲置与周期拉长。

---

## 🎯 适用场景

- ✅ 涉及数据工程、模型开发、后端服务、前端展示等多工种协作的 AI 项目
- ✅ 多个独立模型或功能模块需同时开发
- ✅ 项目时间紧张，需最大化利用人力资源
- ✅ 存在明确依赖链（如数据→特征→模型→API→前端）的开发流程

---

## 🏗️ 核心原则

| 原则 | 说明 |
|------|------|
| **模块解耦** | 将项目拆分为低耦合、高内聚的独立模块，明确输入输出与接口契约 |
| **并行优先** | 对无依赖或仅存在弱依赖（如可通过 mock 数据隔离）的模块，安排并行开发 |
| **串行必要** | 对存在强依赖（数据产出方→消费方、模型→推理接口、接口→前端）的模块，严格按顺序推进 |
| **迭代验证** | 关键节点设置里程碑，采用迭代方式快速验证，减少后期集成风险 |
| **持续集成** | 即使并行开发，也需保持频繁的集成与测试，避免"集成地狱" |

---

## 📝 实施步骤

### 步骤 1：需求分析与模块划分

- 将 AI 项目按功能域分解为一级模块：
  - 数据采集
  - 数据清洗
  - 特征工程
  - 模型训练
  - 模型评估
  - API 服务
  - 前端界面
  - 运维监控等

- 为每个模块定义清晰的：
  - 输入
  - 输出
  - 质量标准
  - 依赖的外部资源

### 步骤 2：依赖关系分析

- 绘制模块依赖图（有向无环图 DAG），标明每个模块的前置依赖项
- 区分依赖类型：
  - **强依赖**：必须等待前置模块完成且产出真实数据
  - **弱依赖**：可通过模拟数据、桩代码先行开发

### 步骤 3：确定并行与串行策略

- **并行组**：将无相互依赖的模块归入同一并行组，可同时启动
- **串行链**：将形成链式强依赖的模块划分为串行路径，按顺序推进
- **关键路径识别**：找出耗时最长的串行链作为项目关键路径，重点保障

### 步骤 4：资源分配与时间规划

- 为每个并行组分配独立的开发人员或团队
- 为串行链中的模块预留缓冲区，避免下游等待
- 使用甘特图或看板，标注并行时间段与串行交接点

### 步骤 5：风险控制与缓冲

- 对弱依赖模块设置"接口先行"策略，并行开发时通过 Mock 数据同步推进
- 为关键依赖节点（如数据准备完成、基模型验证通过）设置检查点，确保产出质量后再触发下游
- 预留时间用于集成调试和模型效果调优（AI 项目特有风险）

## 📊 示例：AI 推荐系统项目

### 模块划分与依赖

| 模块 | 依赖 | 备注 |
|------|------|------|
| A. 用户行为日志采集 | 无 | 可独立 |
| B. 数据清洗与存储 | A | 强依赖 |
| C. 特征工程 | B | 强依赖 |
| D. 模型训练（召回） | C | 强依赖 |
| E. 模型训练（排序） | C | 与 D 无依赖，可并行 |
| F. 模型评估与选择 | D, E | 强依赖 |
| G. 推理 API 开发 | F（真实模型） | 强依赖，但可用 Mock 模型先行开发 |
| H. 前端推荐界面 | G（接口） | 强依赖，但可用 Mock 接口先行 |
| I. A/B 测试系统 | 无 | 可独立并行 |

### 规划策略

```
并行组 1：A、I（无依赖，独立启动）

串行链 1：A → B → C（关键路径开始）

并行组 2：D、E（依赖 C 完成后同时启动）

串行链 2：C → D/E → F → G → H（关键路径主体）

并行组 3：G 与 H 的开发可在 Mock 数据下先行部分工作，待 F 完成后替换真实模型/接口。
```

### 时间线示意

```
周 1-2: A, I
周 3-4: B, C
周 5-6: D, E (并行)
周 7:   F
周 8-9: G, H (部分并行，Mock 先行)
周 10:  集成测试与调优
```

---

## ⚠️ 注意事项

### AI 实验的不确定性
模型训练和调优存在探索性，需在串行链中预留实验迭代时间。

### 数据依赖前置
数据准备往往是 AI 项目的最大瓶颈，应优先启动并设置明确完成标准。

### 接口契约先行
在并行开发时，上下游通过约定 API 契约（OpenAPI/Swagger）解耦，避免等待。

### 持续集成环境
建立自动化流水线，确保并行分支每日集成，及早发现冲突。

## 🛠️ 使用方法

当用户需要规划 AI 项目时，调用此技能并按照以下步骤执行：

1. **收集项目信息**：了解项目目标、模块组成、团队规模
2. **模块划分**：帮助用户将项目拆分为独立模块
3. **依赖分析**：识别模块间的依赖关系（强依赖/弱依赖）
4. **绘制 DAG**：创建模块依赖图
5. **制定策略**：确定并行组和串行链
6. **时间规划**：估算各模块工期，制定时间线
7. **风险识别**：标注关键路径和风险点
8. **输出计划**：生成完整的项目规划文档
