## 📖 示例

### 示例 1：代码审查

**用户请求**:
```
请审查这段代码：
```python
def get_user_data(user_id):
    query = "SELECT * FROM users WHERE id = " + str(user_id)
    result = db.execute(query)
    return result
```

**Agent 响应**:
```markdown
# 代码审查报告

## 总体评估

**审查对象**: get_user_data 函数
**审查时间**: 2026-03-31
**审查范围**: 代码质量、安全性

### 执行摘要

该函数存在严重的 SQL 注入安全漏洞，需要立即修复。函数缺少类型注解和错误处理。

### 评分

**总体评分**: 3/10

**评分依据**:
- 代码质量：5/10
- 安全性：1/10 ⚠️
- 性能：6/10
- 可维护性：4/10

## 审查发现

### 严重问题（Errors）

#### 1. SQL 注入漏洞

**位置**: 第 2 行
**严重程度**: error
**违反规则**: 安全规范 2.1 - 禁止字符串拼接 SQL
**问题描述**: 使用字符串拼接构造 SQL 查询，攻击者可注入恶意 SQL
**影响**: 可能导致数据泄露、数据篡改、权限绕过
**修复建议**: 
```python
def get_user_data(user_id: int) -> dict:
    query = "SELECT * FROM users WHERE id = ?"
    result = db.execute(query, (user_id,))
    return result.fetchone()
```

### 警告（Warnings）

#### 2. 缺少类型注解

**位置**: 第 1 行
**严重程度**: warning
**违反规则**: 编码规范 1.1 - 所有函数必须有类型注解
**问题描述**: 参数和返回值缺少类型注解
**影响**: 降低代码可读性，不利于类型检查
**修复建议**: 添加类型注解（见上方修复代码）

#### 3. 缺少错误处理

**位置**: 第 3 行
**严重程度**: warning
**违反规则**: 错误处理规范 1.2 - 数据库操作需要异常处理
**问题描述**: 数据库执行失败时没有异常处理
**影响**: 程序可能崩溃，错误信息不清晰
**修复建议**: 
```python
try:
    result = db.execute(query, (user_id,))
    return result.fetchone()
except DatabaseError as e:
    logger.error(f"Database error: {e}")
    raise
```

### 建议（Suggestions）

#### 4. 考虑添加文档字符串

**位置**: 第 1 行
**严重程度**: info
**违反规则**: 文档规范 1.1 - 公共函数应有文档字符串
**问题描述**: 函数缺少文档说明
**修复建议**: 
```python
def get_user_data(user_id: int) -> dict:
    """
    获取用户数据
    
    Args:
        user_id: 用户 ID
        
    Returns:
        用户数据字典
        
    Raises:
        UserNotFoundError: 用户不存在时抛出
        DatabaseError: 数据库错误时抛出
    """
```

## 正面发现

- ✅ 函数命名清晰
- ✅ 函数职责单一

## 总结

### 主要风险

1. SQL 注入漏洞（严重）
2. 缺少错误处理

### 优先行动项

1. **立即修复**: SQL 注入漏洞
2. **尽快修复**: 添加错误处理
3. **建议改进**: 添加类型注解和文档

### 下一步建议

1. 修复所有严重问题
2. 添加单元测试
3. 进行代码复查
```
