## 📝 详细阶段

### Phase 1 — 问题发现（Problem Discovery）

**目标**: 理解业务问题和用户需求

**关键指令**: 
- Ask in order. Do not skip any.
- Ask one question at a time.（一次只问一个问题）
- Wait for user response before proceeding.

**标准问题列表**:

#### Q1: 问题定义
```
"这个项目要为用户解决什么问题？"
"What problem does this project solve for its users?"
```

**追问**（如需要）:
- 当前是如何解决的？
- 现有方案有什么痛点？
- 这个问题多久发生一次？

#### Q2: 用户画像
```
"主要用户是谁？他们的技术水平如何？"
"Who are the primary users? What is their technical level?"
```

**追问**（如需要）:
- 有多少用户？
- 用户使用频率？
- 用户的使用场景？

#### Q3: 规模预期
```
"预期的规模是多少？（用户数、数据量、并发量）"
"What is the expected scale?"
```

**追问**（如需要）:
- 预计有多少日活用户？
- 数据量大概多少？
- 高峰期并发量？

#### Q4: 成功标准
```
"如何衡量这个项目的成功？"
"How do you measure the success of this project?"
```

**追问**（如需要）:
- 关键指标是什么？
- 性能指标要求？
- 用户体验标准？

### Phase 2 — 技术约束（Technical Constraints）

**前提**: Phase 1 所有问题已完成并确认

**目标**: 了解技术环境和约束条件

**关键指令**:
- Only proceed after Phase 1 is complete.
- Ask one question at a time.

#### Q5: 部署环境
```
"将使用什么部署环境？（云服务、本地服务器、混合）"
"What deployment environment will you use?"
```

**追问**（如需要）:
- 已有云服务商？（AWS/Azure/GCP）
- 需要容器化？
- CI/CD 要求？

#### Q6: 技术栈偏好
```
"有技术栈偏好吗？（编程语言、框架、数据库）"
"Do you have technology stack preferences?"
```

**追问**（如需要）:
- 团队熟悉的技术？
- 公司技术栈标准？
- 需要避免的技术？

#### Q7: 不可协商需求
```
"有哪些不可协商的需求？（必须实现的功能、必须遵守的规范）"
"What are the non-negotiable requirements?"
```

**追问**（如需要）:
- 必须集成的系统？
- 必须遵守的规范？
- 预算或时间限制？

#### Q8: 依赖关系
```
"有外部依赖吗？（第三方 API、现有系统）"
"Are there any external dependencies?"
```

**追问**（如需要）:
- 需要对接的系统？
- 第三方服务？
- 数据迁移需求？

### Phase 3 — 方案综合（Synthesis）

**前提**: 所有 Phase 1 和 Phase 2 问题已回答完毕

**目标**: 整合需求，制定方案

**关键指令**:
- Only proceed after all questions answered.
- Load the plan template.
- Fill in every section using gathered requirements.

#### 步骤 1: 加载模板
```
Load 'assets/[plan-template.md]'
```

#### 步骤 2: 填充方案

基于收集的需求，填充模板的每个部分：

1. **项目概述**: 基于 Q1-Q4 的回答
2. **技术方案**: 基于 Q5-Q6 的回答
3. **实施计划**: 分阶段规划
4. **风险评估**: 识别潜在风险

#### 步骤 3: 呈现方案

将完整的方案呈现给用户，并说明：

```
基于我们讨论的需求，我制定了以下方案：

[完整方案]

请确认：
1. 这个方案是否准确捕捉了您的需求？
2. 有没有遗漏或误解的地方？
3. 有什么需要调整的吗？
```

#### 步骤 4: 迭代优化

根据用户反馈调整方案：

- 记录用户的修改意见
- 更新方案
- 再次确认
- 直到用户确认（iterate until user confirms）

## 💬 提问技巧

### 好问题的特点

- ✅ 开放式问题（什么、为什么、如何）
- ✅ 具体明确
- ✅ 一次一个
- ✅ 基于上下文追问

### 避免的问题

- ❌ 是/否问题（除非必要）
- ❌ 一次多个问题
- ❌ 引导性问题
- ❌ 假设性问题

### 追问技巧

**用户回答模糊时**:
```
您能具体说明一下吗？
能举个例子吗？
这个功能的使用场景是什么？
```

**需要量化时**:
```
大概的数量级是？
频率是多久一次？
可接受的范围是？
```

**确认理解时**:
```
我理解您的意思是...，对吗？
让我确认一下，您需要的是...？
```

## ⚠️ 注意事项

- **不要猜**: 不确定就问，不要假设
- **不要跳**: 按顺序提问，不要跳过

- **要确认**: 关键信息要确认理解正确
- **要迭代**: 根据反馈调整方案
