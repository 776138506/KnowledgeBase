# WF-01 需求优先级

> 使用 MoSCoW 方法对需求进行优先级排序

## 🎯 MoSCoW 方法

```
M - Must have（必须有）
    核心功能，缺少则系统无法运行
    
S - Should have（应该有）
    重要功能，但可短期妥协
    
C - Could have（可以有）
    期望功能，资源允许时实现
    
W - Won't have（暂不需要）
    未来版本考虑
```

---

## 📊 产出物

### 1. 《需求规格说明书》草稿

包含：
- 项目背景
- 目标用户群
- 功能需求列表
- 非功能需求列表

### 2. 用例图（Use Case Diagram）

**参与者**：
- 主要参与者（发起交互）
- 次要参与者（被动响应）

**用例**：
- 核心业务用例
- 辅助功能用例
- 管理维护用例

**关系**：
- 关联（Association）
- 包含（Include）
- 扩展（Extend）
- 泛化（Generalization）

### 3. 用户故事地图

```
用户活动 → 任务 → 用户故事
```
