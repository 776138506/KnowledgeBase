# 代码注释规范

## 核心原则

1. **代码即文档** - 代码本身说明意图
2. **注释是必要的恶** - 尽量减少
3. **解释为什么** - 不是解释做什么
4. **保持更新** - 陈旧注释更糟

## 好的注释（8 种）

- ✅ 法律信息 - 版权声明
- ✅ 提供信息 - 补充基本信息
- ✅ 意图解释 - 说明决策原因⭐
- ✅ 阐释 - 阐明复杂代码
- ✅ 警示 - 警告潜在风险
- ✅ TODO - 标记待完成
- ✅ 放大 - 强调重要代码
- ✅ 公共 API - Javadoc

## 坏的注释（10 种）

- ❌ 喃喃自语
- ❌ 多余注释
- ❌ 误导性注释
- ❌ 循规式注释
- ❌ 日志式注释
- ❌ 废话注释
- ❌ 位置标记
- ❌ 注释掉的代码
- ❌ 非本地信息
- ❌ 信息过多

## 示例

```typescript
// ✅ 意图解释
// 使用 Map 而不是 Object，因为性能更好
const userCache = new Map<string, User>();

// ❌ 废话注释
const total = price * quantity; // 计算总价
```
