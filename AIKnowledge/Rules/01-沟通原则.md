# AI 协作指南 - 沟通原则

> 有效沟通的四大原则

## 📋 目录

- [明确具体](#1-明确具体)
- [提供上下文](#2-提供上下文)
- [指定约束条件](#3-指定约束条件)
- [定义验收标准](#4-定义验收标准)

---

## 1. 明确具体

```
✅ 好的指令:
"创建一个 React 组件，实现用户搜索功能，包含防抖、加载状态和错误处理"

❌ 模糊的指令:
"做个搜索功能"
```

**要点**：
- 说明具体技术栈
- 列出功能要求
- 指定非功能要求

---

## 2. 提供上下文

```
✅ 包含上下文:
"在现有的用户管理系统中，添加一个批量导入功能。
当前系统使用 React + TypeScript，后端是 Node.js。
需要支持 CSV 和 Excel 文件格式。"

❌ 缺少上下文:
"添加批量导入"
```

**要点**：
- 说明项目背景
- 描述技术栈
- 说明业务场景

---

## 3. 指定约束条件

```
✅ 指定约束:
"使用 TypeScript 实现，需要：
- 类型安全
- 单元测试覆盖率 > 80%
- 符合项目的 ESLint 规则
- 支持错误边界处理"

❌ 没有约束:
"用 TypeScript 写一下"
```

**要点**：
- 技术约束
- 质量约束
- 规范约束

---

## 4. 定义验收标准

```
✅ 明确验收标准:
"功能完成标准：
- [ ] 可以上传 CSV/Excel 文件
- [ ] 显示导入进度
- [ ] 错误数据可下载
- [ ] 有相应的单元测试
- [ ] 通过 ESLint 检查"

❌ 没有验收标准:
"做完告诉我"
```

**要点**：
- 功能验收
- 质量验收
- 文档验收
