# WF-01 需求分析

> 明确系统"做什么"，收集并定义用户需求

## 📋 目标

- 明确系统"做什么"
- 收集并定义用户需求
- 确定需求优先级

---

## 👥 利益相关者

识别所有 stakeholders：

- 客户/甲方
- 最终用户（不同角色）
- 产品经理
- 运维团队
- 业务专家
- 技术团队

---

## 🔍 需求收集方法

| 方法 | 适用场景 | 产出 |
|------|---------|------|
| 访谈 | 深入了解特定用户需求 | 访谈记录、用户痛点 |
| 问卷调查 | 大范围收集用户意见 | 统计数据、优先级 |
| 观察法 | 理解现有业务流程 | 流程图、问题点 |
| 竞品分析 | 了解行业标准 | 功能对比表 |
| 头脑风暴 | 创新功能挖掘 | 创意列表 |

---

## 📝 需求分类

### 功能需求

系统必须提供的功能

**用户故事格式**：
```
作为 [角色]，我希望 [功能]，以便 [价值]
```

### 非功能需求

| 类别 | 说明 | 示例 |
|------|------|------|
| 性能 | 响应时间、吞吐量 | API 响应 < 200ms |
| 安全 | 认证、授权、加密 | 使用 JWT 认证 |
| 可用性 | SLA、容错 | 99.9% 可用性 |
| 兼容性 | 浏览器、设备、系统 | 支持 Chrome、Firefox |
| 可维护性 | 代码规范、文档 | 代码覆盖率≥80% |
