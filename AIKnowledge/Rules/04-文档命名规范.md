# 文档命名规范

> 关于文档命名的最佳实践和建议

## 📋 核心问题

**可以使用中文命名吗？**

**答案**：**可以，但有条件**

---

## ✅ 推荐方案

### 方案 1：英文命名（推荐）⭐

**优点**：
- ✅ 跨平台兼容性最好
- ✅ 版本控制工具友好
- ✅ 命令行操作方便
- ✅ 国际团队通用
- ✅ 避免编码问题

**缺点**：
- ❌ 对英语不好的团队成员有门槛
- ❌ 需要记忆英文含义

**命名规范**：
```
格式：[类别]-[编号]-[描述].md

示例：
- workflow-index.md           # 索引文档
- wf-01-requirements.md       # 需求分析
- design-principles.md        # 设计原则
- tm-01-requirements-template.md  # 模板
- ck-01-requirements-checklist.md # 检查清单
```

### 方案 2：中文命名（可选）

**适用场景**：
- ✅ 纯中文环境团队
- ✅ 不涉及跨平台
- ✅ 团队成员英语普遍不好

**优点**：
- ✅ 直观易懂
- ✅ 降低学习成本
- ✅ 查找方便

**缺点**：
- ❌ 命令行操作需要引号或转义
- ❌ Git 操作时可能显示乱码
- ❌ URL 中会编码为%XX 格式

**命名规范**：
```
格式：[类别]-[编号]-[中文描述].md

示例：
- 00-工作流程总览.md
- 01-需求分析.md
- 02-功能规格定义.md
```

### 方案 3：混合命名（折中方案）

**方式**：
- 文件名：英文
- 文档标题：中文

**示例**：
```
文件名：wf-01-requirements.md
标题：# WF-01 需求分析

文件名：design-principles.md  
标题：# 设计原则
```

## 📝 命名最佳实践

### 1. 统一前缀

**按类别使用前缀**：
```
WF-  : Workflow（工作流程）
TM-  : Template（模板）
CK-  : Checklist（检查清单）
DP-  : Design Principles（设计原则）
```

### 2. 使用小写

**推荐**：
```bash
✅ workflow-index.md
✅ wf-01-requirements.md

❌ Workflow-Index.md
❌ WF-01-Requirements.md
```

**原因**：
- 避免大小写敏感问题（Linux vs Windows）
- Git 对大小写变更处理不一致

### 3. 使用连字符

**推荐**：
```bash
✅ workflow-index.md
✅ wf-01-requirements.md

❌ workflow_index.md      # 下划线
❌ workflowindex.md       # 无分隔
```

### 4. 包含编号

**推荐**：
```bash
✅ wf-01-requirements.md
✅ wf-02-functional-spec.md

❌ wf-requirements.md
```

**原因**：
- 明确执行顺序
- 便于查找和定位
- 支持自动排序

### 5. 保持简洁

**推荐**：
```bash
✅ wf-01-requirements.md
✅ design-principles.md

❌ wf-01-requirements-analysis-and-specification.md
```

**原则**：
- 文件名不超过 50 个字符
- 使用缩写（但要统一）
- 去掉冗余词汇

## 🔧 实际操作建议

### Git 配置（中文环境）

```bash
# 禁用 Git 对中文的转义
git config --global core.quotepath false

# 设置正确的编码
git config --global core.precomposeunicode true
```

## 🎯 最终建议

### 推荐方案：**英文命名 + 中文标题**

**理由**：
1. **技术友好**：文件名英文，避免所有技术问题
2. **易于理解**：标题中文，降低阅读门槛
3. **最佳实践**：符合国际开源项目惯例
